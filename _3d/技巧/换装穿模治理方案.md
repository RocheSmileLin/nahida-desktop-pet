# 换装穿模治理方案（全本地可重复产线）

> 2026-10-16 定稿 · 约束来源：用户明确「**后续会频繁加入新服饰**」+「**云端方案不支持**」
> 适用范围：3D 桌宠（将独立于聊天室）

---

## 0. 目标与硬约束

**目标**：新加一件衣服 → 走一遍**本地产线** → 得到「这件衣服的防穿模数据」→ 桌宠里生效。

**硬约束（决定架构）**：

| 约束 | 含义 |
|---|---|
| ★ **全程本地可重复** | 每一步都必须能在 i5-1235U / 16G / 核显上重跑；**任何一步依赖云端 = 方案作废**（每加一件衣服都要跑一趟云端 ✗） |
| ★ 频繁加衣服 | 产线必须**脚本化、一条命令**；人力只花在「造型」与「最后验收」 |
| 现有分工不变 | 缩放/对位/**造型**=用户手动；拆分/权重/脚本/接线=助手做 |

**一句话**：云端只能用来做**一次性研究**（验证某个方法有没有效），**不能进产线** ✗。

## 1. 问题本质（为什么"这件好那件坏"）

衣服穿模 = 三个因素相乘：

1. **宽松度**：衣服离身体越远，权重差异被放大得越厉害（力臂放大）
2. **绑定位置**：同骨骼不同衣服若绑到不同骨/不同权重剖面 → 姿态一致时位移也不一致
3. **缺机制**：长裙/披风这类**只能靠物理或修正**；关物理时穿模只能"逐件 K 帧"补救

行业结论（已核实）：这是**换装系统的固有问题**，AAA 也一样（UE 论坛：同骨架 + 同物理资产照样穿模）；
`gamedev.net` 模块化换装讨论原话：**"长裙很难，腿总是穿过去，只能上布料物理"** ✓
→ **不是技术选型错，是缺"规范 + 检测 + 逐件修正"这三条流水线**。

## 2. 总体架构（四层，缺一不可）

| 层 | 作用 | 输入 | 产物 | 谁做 | 频率 |
|---|---|---|---|---|---|
| **L1 绑定契约** | **消掉方差**：所有衣服绑到同一张骨名白名单，按宽松度分档 | 新衣服网格 | 权重 + `profile.json` | 我（脚本） | 每件一次 |
| **L2 穿模检测** | **量化验收**：任意姿态下自动测出"哪里穿、多深" | .blend + 姿态集 | 报告 JSON + 标红出图 | 我（脚本） | 每件 + 每次改动 |
| **L3 修正** | 把穿模压到可接受：权重预抬升 / 关键帧 / 驱动形态键 / **学习型修正器** | L2 报告 + 采样数据 | 修正数据（含 `.bin`） | 我（半自动） | 每件一次 |
| **L4 运行时兜底** | 桌宠里每帧最后一道：修正器 + **CPU 去穿透** | 修正数据 | 运行时行为 | 我（接线） | 一次性 |

**关键理念**：L2 产出的一切（姿态→穿模位置）**同时就是 L3 学习型修正器的训练数据** → 一份工，两处用 ✓

## 3. 新加一件衣服的产线（SOP，未来一条命令跑完 ③–⑨）

```
① 造型/留量  ★用户手动★  衣服相对身体留外扩余量；腋下/裆/大腿等危险区拓扑对齐
② 分件 + 命名  我          按材质拆件；材质名=桌宠开关名；贴图节点名 mmd_base_tex
③ 绑定  我（脚本）        按 L1 契约绑到骨名白名单（按宽松度分档）+ 权重和归一化
④ 接物理  我（插件）      插件「接物理」→ 布骨映射到现有 847 刚体驱动的骨链
⑤ 穿模体检  自动          N 个标准姿态 × BVH 碰撞检测 → 报告（哪件/哪姿势/哪部位/多深）
⑥ 修正  半自动            按报告：局部权重预抬升 / 关键帧 / 驱动形态键（重灾区才动）
⑦ 训修正器  自动          采样姿态→形状 → 训练 <1M 参数网络 → 导出 .corrector.bin
⑧ 接运行时  我            桌宠读 .bin（pose→修正量）+ CPU 去穿透兜底
⑨ 复检  自动              同一姿态集再跑 ⑤ → 出前后对比图 + 数字
```

耗时预估（本地，单件）：②③ ≈ 20–40 分钟 · ④⑤ ≈ 30 分钟 · **⑦ ≈ 1–2 小时（可挂着跑）** · ⑧⑨ ≈ 20 分钟

## 4. L1 绑定契约（消方差的核心）

### 4.1 宽松度分档

| 档 | 绑定策略 | 例子 | 说明 |
|---|---|---|---|
| **贴身** | 抄身体权重（就近 z 分层照抄 + 归一化） | 吊带 / 纹身 | 身体怎么动它怎么动 |
| **半贴身** | 抄身体权重 + 向父骨收拢（混 20–40%） | 连衣裙上半 | 减少局部鼓包 |
| **宽松** | **刚绑布骨链**（每段权重≈1），只在腰头/接口过渡 3–5 环 | 裙摆 / 披风 / 大袖 | 段与段独立 → 姿态可控 |

### 4.2 骨名白名单（所有衣服只允许绑这些）
- 躯干：`上半身/上半身2/上半身3/下半身/腰/センター/グルーブ`
- 布链：`Q_*`（裙摆 195 根），`PF*` / `左PF_*` / `右PF_*`（披风 53 根）
- 四肢：`肩/腕/肘/腿/膝/踝` 及其 `D` 付与骨
- **禁止**：绑到 `操作中心` / 无物理的父骨（曾导致"新配件不动"）

### 4.3 命名/材质约定
- 材质名 = 桌宠开关名；新增部件必须同步 `js/settings/20-parts.js` 的 `PART_TREE`
- 贴图节点名必须 `mmd_base_tex`
- 权重和必须 = 1（MMD 蒙皮；<1 桌宠里会散开而 Blender 看不出来）

### 4.4 产物
`_3d\服装\<件名>\profile.json`：记录宽松度档位、骨名白名单、权重剖面参数 → **下次改这件衣服时按它复现** ✓

## 5. L2 穿模检测器（第一个要做的工具）

### 原理
1. 设置姿态（骨骼旋转 / 载入动作 / 载入 .vpd）
2. `depsgraph` 求值 → 取**求值后**的身体网格与衣服网格顶点
3. 身体建 **BVH 树**（`mathutils.bvhtree`）→ 对每个衣服顶点做**最近点 + 内外判定**
4. 输出：穿模顶点索引 / 深度 / 涉及部位

### 输入 / 输出
```
in : .blend + 衣服网格名列表 + 姿态集(动作名/.vpd/自动采样)
out: report.json  { pose, garment, count, max_depth, worst_verts[], by_part{} }
     + 出图：穿模顶点染红叠加
```

### 姿态集（标准化，越早定越好）
- 现有动作的关键帧（小跳/摇腿/坐姿…）
- **危险姿势**（用户手摆后存成 .vpd）：坐、单腿抬、深蹲、弯腰、双手举过头、侧身扭腰
- 自动采样：对下半身/腿/膝/踝/肩/肘做随机旋转组合（用于 L3 训练）

### 判据（回归基线）
`穿模顶点数` + `最大深度(mm)` + `涉及部位` —— 每次改完衣服/权重/修正都跑一遍，**数字不许变差** ✓

## 6. L3 修正

### 6.1 非学习型（先做，成本低）
1. **局部权重预抬升**：危险区（如大腿前侧对应的裙摆段）多分一点给父骨 → 抬腿时裙摆先张开
2. **每件关键帧**：像连衣裙做的那样，在危险姿态写布骨关键帧（**只在静态/无物理动作下有效** ✓）
3. **驱动形态键**：按骨骼角度驱动 morph（Blender 里建驱动 → 导出 PMX morph）

### 6.2 学习型修正器（核心，**全本地可训**）

**思路来源（已核实）**：Meta《Self-Supervised Collision Handling via Generative 3D Garment Models》CVPR 2021
— 在**规范化空间**里学一个"直接输出不穿模形状"的小模型，**自监督（穷举采样 + 碰撞检测）**，**不需要数据集** ✓

**本地化设计**：

```
特征 x : 该件衣服关心的骨骼旋转四元数（约 100–300 维）+ 可选静态量
目标 y : 衣服顶点偏移场，先做 PCA 降到 K=16–32 维系数
模型   : MLP  (in→256→256→K)  ≈ 12 万参数   ← 不是 4B，也不需要 GPU
损失   : 碰撞项(顶点穿入身体的深度)+ 平滑正则 + 幅度正则
训练   : 采样 200–1000 个姿态 → 求 y → 训 20–40 分钟（CPU 可跑）
推理   : pose → 系数 → 基重建 → 顶点偏移      < 1ms
产物   : <件名>.corrector.bin（基 + 网络权重，几十~几百 KB）
```

**老师（y 从哪来）**——两条，先跑通第二条：
- ① MMD 物理（模型自带 847 刚体/493 关节）→ 最自然，但需逐件调参
- ② **CPU 去穿透器**（顶点 vs 身体胶囊体，把顶点推出去）→ 确定性、零调参、瞬间出结果 ✓ **先用它把链路跑通**

---

## 7. L4 运行时（桌宠，three.js）

顺序：`骨骼动画 → ① 修正器(pose→偏移) → ② CPU 去穿透(保底)`

- **修正器**：读 `.bin`，每帧按当前 pose 算系数 → 叠加到顶点属性（几千顶点，JS 里 <1ms）
- **去穿透**：身体用 ~20 个胶囊体近似 → 衣服顶点逐个推出（几千 × 20 ≈ 10⁵ 次距离计算/帧，**< 2ms**）
- **开关**：给用户「防穿模：关 / 修正器 / 修正器+去穿透」

---

## 8. 验收标准（每件衣服）

1. **数字**：体检报告的穿模顶点数与最大深度**不劣于基线** ✓
2. **图像**：姿态集前后对比图（用户按图验收 ✓ 这是既有习惯）
3. **回归**：任何改动后**必须跑完整姿态集** ✓（这条直接消灭"这件好了那件坏了"的随机感）
4. **不改坏**：修正层不许影响正常姿态下的外观（幅度正则 + 只对训练覆盖姿态生效）

## 10. 诚实的边界

- **没有任何方案能做到"任意衣服 × 任意动作"**（AAA 也是逐件修 ✓）；修正器只在**训练覆盖的姿态范围**内可靠 → 对"动作集有限"的桌宠刚好合适 ✓
- **物理是老师**：老师本身抖动/穿透会被学进去 ✗ → 第 4 步必须先调好物理
- 论文方法假设**贴身~中等宽松**；**超长裙/披风**推荐"物理 + 修正"组合
- **不算力焦虑**：本方案无 GPU 需求、无大模型；最重的一步是 CPU 训 12 万参数的小网络（分钟级）
