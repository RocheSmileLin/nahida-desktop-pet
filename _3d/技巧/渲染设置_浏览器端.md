# 浏览器端「渲染设置」（对应 Blender kafetools）

> kafetools 的「场景设置 → 渲染设置」（渲染引擎 / 世界环境 / 透明）在浏览器里能实现到什么程度。
> 位置：调整台右栏 **「渲染」页**（`参数 / 动作测试 / 渲染` 三个页签）。

## 能力对照

| kafetools | 浏览器实现 | 说明 |
|---|---|---|
| 渲染引擎 EEVEE / Cycles | ✅ **材质渲染 / 白模 / 线框** | WebGL 只有光栅化（≈ EEVEE / Workbench）。**Cycles 的路径追踪做不到**（除非上 WebGPU 的路径追踪，成本远超收益） |
| 世界环境（HDRI，如「日落」） | ✅ **无 / 日落 / 清晨 / 正午 / 夜晚 / 室内 / 白棚** | 改的是**灯光颜色 + 强度倍率 + 背景色**，不是真 HDRI（不加载 equirect 贴图，省 GPU） |
| 透明 | ✅ **背景透明** | 画布本来就是 `alpha:0`，勾上后用**棋盘格**表示透明；截图/录屏导出即真透明 |
| 分辨率 / 采样 / 降噪 | ❌ | 浏览器没有采样概念（除非做超采样离屏渲染，`preserveDrawingBuffer` + 多帧累积，成本高） |

## 设置项（写进 `pet_settings.json`）

```json
{ "renderMode": "white", "envPreset": "none", "bgTransparent": false }
```

- `renderMode`：`render` 贴图 / `white` 白模 / `wire` 线框（线框用中灰 `0x8fa3b8`，深浅背景都看得见）
- `envPreset`：`none|sunset|dawn|noon|night|indoor|studio`
- `bgTransparent`：只影响**中央视口**（桌宠窗口本来就是透明的）

## 生效范围

| | renderMode | envPreset | bgTransparent |
|---|---|---|---|
| 中央视口 `viewer.html` | ✅ | ✅ | ✅（棋盘格） |
| 桌面桌宠 `pet.html` | ⛔（宠物不需要白模，未接） | ✅（只改灯光） | ⛔（本来就透明） |

## 两处联动细节

1. `viewer.html` 顶部自带的「渲染 / 白模 / 线框」按钮**也会写回设置**（POST `/petsettings`），所以和右栏下拉框永远同步；
2. 世界环境是**乘在基础配比上**的倍率（`aMul/hMul/kMul/fMul`），所以「整体亮度 / 环境光 / 主光 / 补光」四个滑杆仍然有效，两者不冲突。

## 画质升级（2026-10-17 第二轮：追 Blender EEVEE 的"质感"）

第一轮只有"换颜色"，看着还是平。原因和补法：

| Blender EEVEE 有 | 浏览器原来 | 现在 |
|---|---|---|
| Filmic / AgX 色彩变换 | 线性直出 → 高光死白、暗部发灰 | ✅ **ACES Filmic 色调映射** + **曝光滑杆**（0.5~2.0） |
| 软阴影 | 无阴影 | ✅ **PCFSoft 阴影**（2048 贴图 + 脚下接影平面 + 法线偏移） |
| 世界 HDRI 当环境 | 纯色 | ✅ **9 个真 HDRI 背景**：城市/日落/清晨/夜晚/室内/影棚/森林/庭院（从 `E:/Blender/5.2/datafiles/studiolights/world/*.exr` 转 1024×512 PNG 到 `images/env/`） |
| 环境光染色 | 只有 hemi | ✅ 每个环境带**灯光颜色 + 强度倍率 + 曝光倍率(eMul)** |
| 边缘光 | 无 | ✅ 背后冷光 `rimLight 0.20`（头发轮廓） |

### 关键实现

```js
renderer.toneMapping = THREE.ACESFilmicToneMapping;   // ← 最大的观感差别
renderer.toneMappingExposure = EXPOSURE * p.eMul;      // 每个环境单独校曝光
renderer.shadowMap.enabled = true;
renderer.shadowMap.type = THREE.PCFSoftShadowMap;
keyLight.castShadow = true;   // 2048 贴图 / bias -0.0008 / normalBias 0.02
mesh.traverse(o => { if (o.isMesh) { o.castShadow = o.receiveShadow = true; } });
// 脚下接影：ShadowMaterial（只接影不画自己）
```
背景：`stage.style.background = '#0b0e13 url(images/env/city.png) center/cover no-repeat'`
（勾「背景透明」时换成棋盘格，HDRI 图不生效）

### 还差什么（真要 1:1 追平 EEVEE 的话）

1. **真 IBL 反射**：这个模型用的是 `MMDToonMaterial`（卡通材质），不吃 `scene.environment`，
   所以 HDRI 只能当"背景图 + 手动灯光染色"，进不到材质反射里；
   想让头发出现 HDRI 高光，要么给材质加 matcap/sphere 强度，要么整批换 `MeshStandardMaterial`（会失去卡通感）。
2. **AO / 屏幕空间 GI**：需要 `postprocessing` 那套（EffectComposer + SSAOPass），体积大、低端核显掉帧风险高。
3. **Cycles 路径追踪**：浏览器没有，除非上 WebGPU 自建，基本不考虑。

## 三渲二（原神风）

渲染引擎多了一项 **「三渲二（原神风 · 彩色色阶）」**。四要素：

1. **整块换材质**：`MMDToonMaterial` 其实是 **Phong + matcap**（`MMDToonShader.js` 里只有 `TOON:true` 这个 define，
   没有任何色阶代码）→ 所以**改它的 `gradientMap` 完全无效**，必须换成 `MeshToonMaterial`；
2. **彩色 ramp**（canvas 128×1，`getToonRamp()`）：
   ```
   0~58%  #4d527a   ← 阴影：冷紫（原神的影子偏蓝紫，不是变黑）
   58~62% 过渡
   62~90% #c6cbd8   ← 中间调
   90~100% #ffffff  ← 受光
   ```
   three 的 toon shader 是 `diffuse * texture2D(gradientMap, NdotL).rgb` ⇒ **ramp 里写什么颜色，阴影就是什么颜色**。
   ⚠️ three 内部做了 `dotNL = 0.5*dotNL + 0.5`，所以 ramp 坐标 **0.5 = 与光垂直**，写 0.4 以下等于只给背面；
3. **脸部柔和斜坡**（`getFaceRamp()`，暖灰阴影 `#a39499`、过渡很宽）：
   原神的脸不吃硬阴影，共用身体 ramp 的话鼻子/下巴会出现硬黑边；靠 `FACE_RE` 匹配材质名（颜/肌/颈/口舌/齿/耳）自动切换；
4. **压环境光、抬主光 + 灯改成前光**（三渲二模式内）：`ambient×0.5 / hemi×0.55 / key×1.5 / fill×0.7`，
   且 `keyLight` 挪到 `(0.35,0.60,1.0)`（原神角色永远是前光，否则竖直面整块落在阴影色阶里）。

### 描边（反向外扩壳）

`MeshBasicMaterial{ side: BackSide }` + `onBeforeCompile` 注入 `transformed += normalize(normal) * uOutlineW`，
每个材质建一个壳材质、共用同一份几何（`SkinnedMesh` 共享 skeleton），所以**蒙皮/形态键自动跟随**。

宽度单位是**场景单位**（模型约 15 单位高），面板「描边宽度」0~15 → `×0.01`；默认 **5**（≈1px）。

#### 描边踩的五个坑（全部实测过）

| 现象 | 根因 | 解法 |
|---|---|---|
| 点「三渲二」没反应 | `MeshBasicMaterial` 没有 `objectNormal`（那是带光照材质才有的变量） | 注入点改成 `<begin_vertex>` 之后 + 用 `normal` 属性 |
| 描边完全看不见 | 宽度按 mm 给了 0.0016，模型是 **15 场景单位**高 → 0.01% 身高 | 宽度按场景单位给（0.05） |
| 裙子整块变紫/变红 | 裙子是 `transparent`+`alphaMap`（或法线朝内），**不透明壳从里面透出来 / 近侧面被当成背面** | 壳强制不透明只用 `alphaTest`；法线朝内的组（`groupNormalSigns()` 逐组算 dot(normal, 顶点−球心)）翻转 `side` + 反向外扩 |
| 薄片布料整片被壳盖住 | **单面片**（裙/披/飘带）没有内外之分，反向外扩壳必然盖穿 | `CLOTH_RE` 匹配的布料类材质**跳过描边**（只给身体/头发/四肢描边） |
| 换装件全冒出来 | 部件显隐靠 `material.name`，新材质没继承名字 | `toonMat.name = 原材质名` |

### 照片级调色：对比度 / 高光 / 阴影（后处理）

调整台「渲染」页新增三个滑杆，**浏览器视口和桌面桌宠同一套**（都走同一份 `pet_settings.json`）：

| 控件 | 范围 | 说明 |
|---|---|---|
| 对比度 | 0.5~2（默认 1） | 大于 1 加对比、小于 1 往中灰压 |
| 高光 | -1~1（默认 0） | 正值提亮亮部、负值压回高光细节 |
| 阴影（暗部） | -1~1（默认 0） | 正值提亮暗部、负值压暗 |

实现：**渲染到贴图 → 全屏 quad 上色**（材质侧改不了，白模/线框/MMD/Toon 各有各的 shader）。
调色三项都为中性时走直出，不付额外开销。

#### 三个坑（全部实测踩过）

1. **RT 里是线性值，不是 sRGB** —— r144 渲染到 RT **不走** `outputEncoding`，
   所以 shader 里必须自己 `pow(c.rgb, 1.0/2.2)` 转显示空间；忘了转整幅图会暗一大截（实测 144 → 96）；
2. **RT 不能用 8 位存线性值** —— 暗部会被量化抬高（83 → 98），必须用 `HalfFloatType`；
3. **对比度不能用线性拉伸** —— 这个角色以白色为主，线性拉伸会把白衣直接推到 255（实测中位数 p50 变 255、p99 全爆）。
   改成 **端点不动的 S 曲线**（`smoothstep` 混合），实测对比度 2.0 时 p50 193→216、剪白占比仍为 0%。

调色在**显示空间**（sRGB）里做，和 PS 的调整图层一致。

### 阴影（模型自投影 + 地面接影）

| 控件 | 浏览器视口 | 桌面桌宠 |
|---|---|---|
| **阴影开关**（`shadowOn`） | 模型自投影 + 地面投影 | **模型自投影**（无地面） |
| **地面接影浓度**（`shadowOpacity`） | 脚下接影平面浓度 | —（没有地面） |
| **阴影清晰度**（`shadowSize`） | shadow map 分辨率 | 同左（默认 1024 省 GPU） |

「模型自投影」才是层次的主要来源：刘海→脸、披风→身体、裙摆→腿。
实测桌宠开/关：下巴/脖颈 114 vs 125、躯干 103 vs 113（开=更暗），全图 **1.94%** 像素差。

⚠️ 这里踩了个大坑：**阴影之前其实一直没生效** —— `keyLight.shadow.camera` 的取景范围写的是
`left/right ±1.0、top 1.4`（按 1 米模型配的），而 MMD 模型有 **~15 场景单位** ⇒ 模型整个在阴影相机之外，
所以改浓度/开关都看不出差别（实测 0.00% 像素差）。

现在的做法：

1. 模型加载后按包围盒算 `SHADOW_R = max(6, 包围盒对角线 × 0.55)`；
2. 阴影相机按 `SHADOW_R` 重设（`±R`、`top 1.6R`、`bottom -0.6R`、`far 8R`）；
3. 光源位置改成 `方向.normalize() × SHADOW_R × 2.5`（方向光只认方向，但阴影相机是摆在 `position` 上的，必须放远）；
4. 脚下接影平面 `8×8` 按 `SHADOW_R/4` 缩放，保证盖住 2×SHADOW_R；
5. 改分辨率后必须 `shadow.map.dispose(); shadow.map = null;`，否则 three 不会重建 shadow map。

实测（浓度 0.32/精度 2048 vs 关）：全图 **5.2%** 像素差、下半区 2.8%、脚下平均亮度 106 → 102；
浓度 0.9 时脚下 99。

> PCFSoftShadowMap 会**忽略** `shadow.radius`，所以"柔和度"只能靠改分辨率来实现。



### 桌宠端开关（右键菜单）

桌宠（`pet.html`）里也有同一套三渲二，**开关在右键菜单里，和「物理效果」并列**：

```
右键 → ● 物理效果：开 / 关
        ○ 三渲二：关 / ● 三渲二：开      ← 新增
```

- 默认关；点一下立即生效（换材质 + 建描边壳 + 重算灯光），再点回原材质；
- **记忆开关**：状态写回 `pet_settings.json` 的 `toonOn`，**重启桌宠后自动恢复**；
  调整台「渲染」页也有一个「三渲二（桌宠）」勾选框，两边同步；
  ⚠️ 从设置推过来时不回写（`setToonOn(on, true)`），否则会和轮询互相激发；
- 描边宽度读 `PET_SETTINGS.outlineWidth`（调整台「渲染」页那个滑杆，×0.01=场景单位）；
- 桌宠的材质在加载时就被换成了 `MeshLambertMaterial` → 三渲二是**在 Lambert 之上再换一次**，
  所以原材质参数（map / color=0xe6e6e6 / alphaTest 0.02）都取自 Lambert 版；
- **`opacity < 0.02` 的材质不参与换材质**（`踝饰-足.L/.R` 实测 opacity=0）——
  三渲二材质强制 `opacity=1`，不跳过的话这些"本该隐形"的部件会冒出来；
- 描边壳的 `visible` 绑定 `S.revealed`：入场素材没齐时壳也必须藏，否则会先冒出一圈黑边；
- 调试：`pet.html?toon=1` / `?toon=0` 可在加载完成后直接开关（无头截图验证用）。

### 模型就绪必须重跑一次 setMode

`setMode()` 首次执行时 **`S.mesh` 还是 null**（材质已登记但模型对象还没赋值），
所以里面的 `applyParts()`（部件显隐）、`buildOutlines()`（描边）全是空跑 ——
曾导致「三渲二模式下隐藏的裙子全冒出来」。解法：模型就绪（站姿就绪那段）末尾再 `setMode(MODE)` 一次。

| 参数 | 作用 |
|---|---|

| `ow=0.05` | 描边宽度（场景单位）|

## 三条坑

1. **`applyLighting()` 里必须回掉 `applyEnv()`** —— 否则拖一下「整体亮度」，世界环境的颜色/倍率就被覆盖回默认；
2. 桌宠的 `PET_SETTINGS` 必须声明新键（`renderMode/envPreset/bgTransparent`），
   否则 `applySettings` 的 `hasOwnProperty` 过滤会整包丢掉（`expr`、`eyeUp` 都踩过）；
3. `js/pet/10-scene.js` 里 `ENV_PRESETS` 定义在 `applyLighting` 之后，函数首帧可能先跑到 —— 所以取值处要写
   `typeof ENV_PRESETS !== 'undefined' && ENV_PRESETS[...]` 的兜底。
