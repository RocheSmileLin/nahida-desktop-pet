# 面部表情怎么制作（MMD/PMX 模型 + 桌宠）

> 适用：`E:\QQTwinBot\_3d` 的纳西妲模型（主体 **92 个形态键**，其中 **65 个是真表情**）
> 生成时间：2026-10-17 · 只读核对过 Blender 实测数据

---

## 〇、先分清三种"做表情"

| 目的 | 改什么 | 要不要重导 PMX |
|---|---|---|
| ① 让现有表情**动起来**（笑一下、眨眼、说话口型） | 动作文件（VMD）里的**表情轨道** | 不用 ✅ |
| ② 做一个模型里**没有**的表情 | Blender 里新增**形态键** → 注册成 morph | **要** ✅ |
| ③ 让桌宠**按逻辑**摆表情（开心/生气/说话） | `js/pet/50-expressions.js` 里写 `morphTargetInfluences` | 不用 ✅ |

## 一、模型里已经有的表情（不用自己做）

主体形态键（按用途分）：

| 类别 | 名字 |
|---|---|
| 口型（あいうえお） | `あ` `い` `う` `え` `お` `あ２` `い１` `い２` `ワ` `ん` `ω` |
| 嘴形 | `にやり` `にやり２` `にやり３` `口角上げ` `口角下げ` `口横広げ` `口横狭め` `舌広げ` `てへぺろ` `ぺろっ` |
| 眼睛/眨眼 | `まばたき` `ウィンク` `ウィンク右` `ウィンク２` `ウィンク２右` `じと目` `ジト目` `眼角上` `眼角下` `下眼上` `瞳小` `星目` `ハイライト消` |
| 情绪 | `笑い` `なごみ` `にこり` `怒り` `悲しむ` `困る` `びっくり` `真面目` `恥ずかしい`（每个还有 `〜左` / `〜右` 单边版） |
| 视线 | `上` `下` `前`（+ 左右单边版） |
| 别碰的 | `Basis` `mmd_sdef_c` `mmd_sdef_r0/r1`（SDEF 内部用）、`Base` `Na` `Fitness` `fix*` `Breast*` `18+` 等身体形态 |

⚠️ **VMD 里的表情名 = 15 字节 Shift-JIS**（和骨名一样的限制）
⇒ 名字只能用**日文/ASCII**；用简体中文（如「微笑」「生气」）写进 VMD 会**直接失配、表情不动**，而且不报错。

## 二、做表情动画（不改模型，推荐先走这条）

表情动画 = VMD 里的**表情（morph）关键帧**：`骨名/表情名 15 字节 + 帧号 4 + 权重 4（0~1）`。
一个动作文件可以同时含骨骼轨道和表情轨道，桌宠/MMD 会一起播。

### 路线 A｜Blender 里 K 帧再导出（最直观）
1. 选 `纳西妲_13_主体`（或整套模型）；
2. 属性 → **物体数据属性 → 形态键**，选中要做的表情（比如 `にこり`）；
3. 把「值」拖到 1.0，**在这一帧按 I 键**（或右键值 → 插入关键帧）；
4. 到别的帧把值改回 0 再 K 一次 → 就有了「笑一下再收回」；
5. 导出动作：`mmd_tools` 面板 → **VMD 导出**（`mmd_tools.export_vmd`）→ 得到带表情轨道的 VMD；
6. 把 VMD 放进 `_3d\motion\`，在 `motions.js` 的 `MOTION_DEFS` 里加一条，然后跑
   `python39.exe _3d/_check_sync.py` 自检 ✅

### 路线 B｜直接写 VMD 表情轨道（批量/程序化）
表情帧结构（VMD 里骨段之后的那一段）：
```
uint32  表情帧数量
每条：
  char[15] 表情名（Shift-JIS，不足补 0）
  uint32   帧号
  float    权重 0~1
```
适合批量生成（比如"每 4 秒眨一次眼"这种）。本项目的 `_3d\临时文件\_vmd_pingpong.py` 已经是现成的 VMD 读写骨架，改一改就能写表情轨道。

## 三、新增一个模型里没有的表情（要重导 PMX）

1. **复制一个相近的表情当底**（比从零拉顶点快得多）：
   形态键面板 → 选中 `にこり` → 下拉菜单 **复制形态键**（不要动 `Basis`！）；
2. 选中新键 → **值设 1.0** → 进**编辑模式**只动脸部的点（嘴角/眼角/眉）；
   ⚠️ 只动脸，别碰眼球/牙齿以外的部位，否则张嘴时会破面；
3. 回物体模式，把值调回 0（编辑的是"差值"，值 0 才是正常脸）；
4. 在 `mmd_tools` 的 **Morph 面板**里注册成 PMX 表情：
   - 顶点表情：`morph_add` → 类型 `Vertex` → 指定形态键；
   - 或做**组表情**（Group）：把已有表情组合，例如
     `私の笑顔` = `にこり` 0.8 + `口角上げ` 0.5 + `まばたき` 0.0 —— 不用新几何，最好维护 ✅
5. **名字 ≤ 15 字节且是 Shift-JIS 可编码字符**（日文/ASCII）。要中文显示就写 `name_e`（英文名），
   MMD/VMD 靠 `name_j` 匹配；
6. 导出 PMX → 桌宠重新加载（`model\纳西妲完美版.pmx`）。

## 四、桌宠侧怎么驱动表情

`js/pet/50-expressions.js` 里已经有一套现成机制（morph 索引在 `js/pet/60-model.js` 建表）：

```js
/* 名字 → 索引 查表（S.morphIdx 由 60-model.js 填充） */
S.morphIdx['まばたき']   // → 索引
/* 写值：0~1 */
S.mesh.morphTargetInfluences[S.morphIdx['にこり']] = 0.8;
```

⚠️ **关键坑**：`frame()` 每帧都会 `resetMorphs()` 把所有表情清零（防"上一个动作的表情卡住"，
这是踩过的坑：曾出现索引 21 的 morph 卡在 0.94、脸一直眯着）。
⇒ 你程序化设置的表情**必须每帧重写**，写一次会在下一帧被清掉。

现成例子是 `applyExpr()`：先把 `PET_SETTINGS.expr` 写进 morph，再跑自动表情。
想加"情绪表情"，照抄这段写一个 `setExpression(name, w)` 放进 `frame()` 里即可。
（★ 原来的程序化眨眼状态机已在 2026-10-18 按用户要求删除，现在眼睛完全由表情/动作驱动。）

## 五、五个坑（都在这个项目里踩过）

1. **VMD 表情名 15 字节 Shift-JIS** —— 中文名会静默失配；
2. **每帧被清零** —— 程序化表情要持续写（见上）；
3. **多表情叠加会炸**：`あ` + `にやり` 同时 1.0 时嘴角会翻出去。
   同时多个表情时权重总和控制在 ≤1，或分开不同部位（眼 + 嘴可以各 1.0）；
4. **别用"缩放眼骨"做闭眼** —— 模型有 `まばたき`，缩骨会导致眼皮错位（早先踩过）；
5. **形态键顺序**：删/插形态键会改变 three.js 里的 morph 索引，
   所以代码里**永远按名字查 `S.morphIdx`**，不要写死数字 ✅

## 六、视线（眼球方向）≠ 形态键 —— 必须转骨（2026-10-17 实测）

「上 / 下 / 前 / 上左 / 上右 / 下左 / 下右 / 前左 / 前右」这 9 个名字看着像视线，
**其实是眉毛**。用 Blender 量化（`临时文件/_morph_scan.py`）：

| 形态键 | 动的顶点数 | z 范围 | 与眼睛（まばたき/ウィンク 的顶点集）重叠 |
|---|---|---|---|
| `上` | 56 | 0.992~0.999 | **0.0%** |
| `下` / `前` | 56 | 0.992~1.026 | **0.0%** |
| `上左`…`前右` | 每个 28 | 同上 | **0.0%** |
| 真眼睛键（まばたき/ウィンク/じと目…） | 587~1390 | 0.938~0.999 | 98~100% |

z 比眼睛高 2~3cm ⇒ 眼睛上方 = 眉毛。所以把这几项当成"视线"拧，只会看到眉毛动。

**眼球在哪**：虹膜 228 个顶点，权重挂在 `左目` / `右目`（各 114 点，权重和 ~51）。
转这两根骨 25° → 虹膜平均位移 13.6mm（`临时文件/_iris_bone_test.py` 实测）。

### 落地要点

1. **骨名有两套**（本项目特有坑）：`.blend` 里中文化成 `眼.L / 眼.R / 双眼`，
   但**导出的 PMX 里还是 MMD 原名的 `左目 / 右目 / 両目`**。
   代码必须两套都认，否则 `applyRot('眼.L')` 找不到骨会**静默跳过**（桌宠的鼠标视线就这样白跑了很久）：
   ```js
   S.eyeNames = (S.bones['眼.L'] && S.bones['眼.R']) ? ['眼.L', '眼.R']
              : (S.bones['左目'] && S.bones['右目']) ? ['左目', '右目'] : [];
   ```
2. **幅度别太大**：这个模型的虹膜是**贴片**（薄片），转 22° 会把贴片转到侧面 → 看起来像**闭眼**。
   实测 **12° 自然**（眼睛仍睁开、虹膜明显上移），面板默认 `eyeMax = 12`，可调 0~30。
3. **叠加方式**：桌宠走 `applyRot(眼骨, 垂直, 水平, 0)`（+= 叠加在动作/鼠标跟随之上）；
   中央视口走"静止四元数 + 增量"的绝对写入（静态按需渲染，避免逐帧累加漂移）。
4. 滑杆对应设置项 `eyeUp / eyeDown / eyeLeft / eyeRight / eyeMax`（**必须写进 `PET_SETTINGS` 默认值表**，
   否则 `applySettings` 的 `hasOwnProperty` 过滤会整包丢掉 —— `expr` 也踩过这个坑）。

## 七、新增「眼眶雕刻」形态键（2026-10-17，已接入面板）

为了有**高自由度的表情塑造**，在 `纳西妲_13_主体` 上新增了 10 个形态键
（92 → 102 个；PMX 里 morph 200 → **210**）。内部名用 ASCII，**保证 Shift-JIS 安全**
（中文名放面板显示层）：

| 形态键名 | 面板中文 | 做法 |
|---|---|---|
| `eye_up` | 上眼眶上抬（睁大上缘） | 反向 `まばたき` 的位移（仅上眼皮、dz<0 的 1160 点）×0.95 |
| `eye_up_dn` | 上眼眶下移 | **正向** `まばたき`（同一批 1160 点）×0.95 → 1.0 = 闭眼，0.3~0.5 = 半睁 |
| `eye_dn` | 下眼眶下移 | 反向 `下眼上`（298 点） |
| `eye_dn_up` | 下眼眶上移 | **正向** `下眼上` ×1.4（302 点，最大 4.9mm；原 delta 只有 3.5mm 所以放大） |
| `eye_tall` | 眼眶拉高（上下同时） | `eye_up` + `eye_dn` |
| `eye_squint` | 眼眶压扁（眯眼） | `まばたき`×0.6 + 反向 `下眼上`×0.6（上压下抬） |
| `eye_wide` | 眼眶加宽 | 眼区 1471 点沿 x 向外 5mm，smoothstep 衰减 R=32mm |
| `eye_narrow` | 眼眶收窄 | 同上向内 4mm |
| `eye_sink` | 眼窝凹陷 | 沿 +y（头朝 -Y）5mm，同样衰减 |
| `eye_bulge` | 眼窝凸出 | 沿 -y 5mm |

眼区顶点集 = `まばたき ∪ 下眼上 ∪ 眼角上 ∪ 眼角下 ∪ ウィンク`（1471 点）；
眼中心（Blender 世界坐标）= `(±0.0455, -0.0809, 0.9728)`。

### 怎么自己改这几个键（雕刻）

1. 选中 `纳西妲_13_主体` → **物体数据属性 → 形态键**（Shape Keys）；
2. 点中要改的 `eye_*` 键，把 Value 拉到 1；
3. 进**编辑模式**，只选眼眶区域顶点，用 `G` / 雕刻工具改形；
   ⚠️ 必须在「该形态键被选中且 Value=1」的状态下改，改完 Value 归 0；
4. 退出物体模式 → `Ctrl+S` → 跑 **`_3d/tools/导出PMX.py`** 重导 PMX；
5. 重启 `pet_app.py`（桌宠加载的是 `model/纳西妲完美版.pmx`），面板会自动多出新滑杆
   （名单由桌宠上报 `/petmorphs`，**不需要改 settings.html**）。

### 四个坑

1. **导出必须 `visible_meshes_only=False`** —— 服装/配件在视口里是隐藏的，否则整批丢失；
2. **导出的是内存场景** → 先在 Blender 里 `Ctrl+S`，否则重导回旧几何；
3. 新增形态键**追加在末尾**（索引 92~99），three.js 的 morph 索引会变 ——
   代码里一律按名字查 `S.morphIdx`，不能写死数字；
4. **`shape_key_add()` 建出来的键，滑块默认值是 1.0**（不是 0！）——
   建完必须 `key.value = 0`，否则视口里会把所有新形变叠加显示，看起来像模型被拉变形。
   （只影响视口显示，PMX 导出的是相对 Basis 的偏移，不受影响；但很容易吓一跳）

### 嘴巴 / 舌头（10 个，2026-10-17 第二批）

嘴区顶点 = 14 个口型键的并集（`あ い う え お あ２ ワ ん にやり 口角上げ 口角下げ 口横広げ 口横狭め ω`）
= **672 点**，中心 `(0, -0.0912, 0.9257)`。

**舌头 = 96 点** —— ⚠️ 不要用 `てへぺろ/ぺろっ` 的顶点集（385 点）！
那两个键**同时带动嘴唇**（各含 96+96 点的唇形），按它算会把"舌头控制"做成"嘴巴控制"。
正确取法：材质 `口舌` 的 4 个连通块里，**那对 48+48** 才是舌头（x ±0.0104 / y −0.0972~−0.0779 / z 0.9248~0.9285），
另外的 54+50 是口腔内壁（上颚 + 口腔底）。
舌尖 y=**−0.0972**、舌根 y=−0.0779（模型面朝 **−Y**，y 越小越靠前）。

| 形态键名 | 面板中文 | 做法 |
|---|---|---|
| `mo_wide` | 嘴巴加宽 | 按 x 相对中心缩放 ×0.22（最大 7.9mm） |
| `mo_narrow` | 嘴巴收窄 | 同上 ×−0.18（6.5mm） |
| `mo_up` / `mo_dn` | 嘴巴上移 / 下移 | 整体 z ±4mm |
| `mo_fwd` / `mo_back` | 嘴巴前凸 / 内凹 | 整体 y ∓4mm |
| `tg_out` | 舌头伸出 | 沿 −y，max **16mm**，按离舌尖远近加权（舌根不动） |
| `tg_up` / `tg_dn` | 舌尖上抬 / 下压 | z ±7mm，同样尖端加权 |
| `tg_wide` | 舌头加宽 | x 比例 ×0.35，尖端加权（最大 2.7mm） |

验收口径（很重要）：**舌外顶点位移必须是 0**。
实测 `tg_out/tg_up/tg_dn/tg_wide` 在 96 点之外的**最大偏差 = 0.000000 mm** ⇒ 嘴唇、皮肤（1292 点）完全不受影响 ✅
（旧版按 385 点做的时候，唇形会跟着动 → 用户反馈"像控制嘴巴，而不是舌头本身"）

⚠️ **舌头只有张嘴（`あ`）或 `tg_out` 拉得够大时才看得见** —— 它本来在口腔里，
闭嘴状态下推出去会从嘴唇穿出来（穿模），配合 `あ` 一起用。
